# Kubling CLI <Tag description={"KDV v26.3+"} />

The Kubling CLI, invoked as `kdv`, creates and manages version-controlled
Kubling projects. A project keeps its runtime configuration, Modules, Compose
services and tests together.

Use the [Quickstart](/quickstart) to evaluate Kubling. Use KDV when the
configuration, tests and deployment inputs must become a maintained project.

## Scope

KDV provides the Kubling-specific project workflow:

- create projects from maintained starters
- validate and build configuration, descriptors and Modules
- run isolated JavaScript tests and Compose-based integration tests
- manage named development instances through Docker Compose
- prepare deployment artifacts, TLS material and an optional Helm scaffold

KDV does not embed or replace the Kubling runtime. It uses the project
environment's selected image for local workflows and exports the artifacts
needed by the production delivery model.

## Tool boundaries

| Tool | Responsibility |
| --- | --- |
| KDV | Kubling project validation, builds, tests and local instance lifecycle |
| Docker Compose | Kubling, providers, supporting services, volumes and integration-test services |
| Make | Optional shortcuts for the local and CI workflow |
| Docker | Optionally build and publish a project-specific runtime image |
| Helm or GitOps | Deploy and reconcile the generated Kubernetes resources |
| Artifact repository | Publish versioned Modules and externally delivered runtime bundles |

KDV is distributed as `docker.io/kubling/kubling-cli`. Generated projects
include a launcher pinned to the KDV version used to create them.
