# Install KDV

KDV is available as a native command-line package and as an official container
image. Both channels expose the same `kdv` command, project format and build
outputs.

<Callout type="info">
  The CLI examples use the official container image for compatibility across
  development machines and CI environments. Projects generated by KDV include
  a version-pinned `./kdv` launcher that follows the same container-based
  workflow.
</Callout>

## Choose a distribution channel

<Cards num={2}>
  <Cards.Card title="Debian and Ubuntu" href="#debian-and-ubuntu" arrow>
    Install `kdv` as a host command and manage it through the official Kubling
    APT repository.
  </Cards.Card>
  <Cards.Card title="Container image" href="#container-image" arrow>
    Run the portable image used by the documentation, generated launchers and
    CI workflows.
  </Cards.Card>
</Cards>

| Channel | Use it when | Release selection |
| --- | --- | --- |
| Native package | KDV should be installed and upgraded by the host package manager | Package version |
| Container image | The same isolated CLI should run across developer machines and CI | Image tag or digest |

The distribution channel changes how KDV reaches the host, not how projects
are authored. Additional package formats can be added without changing the
commands used throughout the remaining guides.

## Debian and Ubuntu <Tag description={"KDV v26.5+"} />

First [configure the Kubling APT repository](/install/debian). Then install the
CLI package and verify the command:

```shell copy
sudo apt-get update
sudo apt-get install kubling-cli
kdv --version
```

The package installs `kdv` as a host command. Commands that start or test a
project environment still require Docker Engine, Docker Compose v2 and access
to the selected Docker daemon.

Create a project directly from the installed command with:

```shell copy
kdv project init my-project
```

The generated project includes its own `./kdv` launcher. Keep that launcher
under version control so the project uses its selected CLI release instead of
depending on whichever package version happens to be installed on a host.

## Container image

Pull and verify an explicit CLI release:

```shell copy
docker pull docker.io/kubling/kubling-cli:<tag>
docker run --rm docker.io/kubling/kubling-cli:<tag> --version
```

The image expects a project workspace at `/workspace`. The
[create a project](/cli/first-project) guide provides the complete bootstrap
command and continues with the generated `./kdv` launcher.
