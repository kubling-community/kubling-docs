# Kubling Data Source (`KUBLING`)

A Kubling instance can use another Kubling instance as a data source. This
allows teams to federate independently managed VDBs while exposing a unified
catalog to clients.

`KUBLING` is a [database data source](/engine/ds/db-data-sources), so it
supports passthrough mode and additional-column configuration.

## When to use independent instances

- Separate operational or security boundaries between data domains
- Keep data source configuration and lifecycle under the team that owns it
- Distribute expensive source access or scripting workloads across instances
- Compose a higher-level VDB without moving the underlying data

<Callout type='info'>
  A federation of Kubling instances is not a cluster. Runtime state such as
  cache entries remains private to each instance.
</Callout>

## Topology discovery <Tag description={"v26.7+"} />

The query transport and the management endpoint are configured separately.
Add `managementEndpoint` when this link should be traversable through the
[federation topology API](/engine/admin/topology):

```yaml copy
dataSources:
  - name: "warehouse"
    dataSourceType: "KUBLING"
    configObject:
      dataSourceName: "warehouse-kubling"
      serverAddress: "warehouse.internal"
      serverPort: 35482
      databaseName: "Warehouse"
      userName: "{{ KUBLING_FEDERATION_USER }}"
      token: "{{ KUBLING_FEDERATION_TOKEN }}"
      managementEndpoint: "https://warehouse.internal:8282"
```

Without `managementEndpoint`, the data source remains queryable but the
topology API reports the link as not discoverable.
