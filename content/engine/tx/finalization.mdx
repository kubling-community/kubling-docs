# Commit, rollback and compensation

Kubling coordinates one transaction outcome, but each participant completes it
according to its own capabilities.

| Participant | Commit | Rollback |
| --- | --- | --- |
| Native database transaction | The database commits its enlisted branch. | The database rolls back its enlisted branch. |
| Provider-native transaction | The provider commits its bound native transaction. | The provider rolls back its bound native transaction. |
| Deferred Soft Transaction | Kubling applies the recorded mutations. | Unapplied mutations are discarded; an applied prefix is compensated. |
| Immediate Soft Transaction | Mutations are already visible; commit records the successful outcome. | Kubling compensates applied mutations. |

## Compensation

Compensation is the rollback mechanism for an external effect that has already
occurred and cannot be rolled back natively. Kubling records the compensating
work as part of the Soft Transaction state and applies it in reverse mutation
order.

Compensation is not equivalent to native rollback:

- the external effect may have been visible before compensation
- another system may already have reacted to it
- a compensation can fail or become unsafe to repeat
- some side effects are inherently irreversible

<Callout type="warning">
  Do not enable Soft Transactions for a mutation unless its compensation is
  valid for the source and acceptable to the application.
</Callout>

## Failure during completion

Kubling stops the successful completion path when a participant fails. Native
participants follow their transaction contract. For a Soft Transaction,
Kubling retains the durable state needed to continue a known rollback or report
an unresolved external outcome.

A failed compensation is not reported as a successful rollback. Its journal
record and row locks remain available for recovery or operator intervention.

## Timeouts

When a transaction reaches its deadline, Kubling starts rollback. The rollback
grace period limits how long that cleanup can continue before interruption; it
does not extend the transaction deadline.

Configure the grace period above the longest participant rollback deadline.
See [Timeouts and recovery](/engine/tx/recovery) for the application descriptor
and restart behavior.
