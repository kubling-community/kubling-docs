# Product changelog

## v26.5

- Introduced Preview [semantic federation](/semantics), allowing each VDB to
  acquire, validate, compose and activate versioned semantic Modules and
  optional provider fragments.
- Added [Logical Query v1](/semantics/logical-query), a structured query
  contract that Kubling validates against the active VDB catalog and semantic
  model before compiling it to SQL.
- Added the Preview [native capability Task API](/agent/intro) for bounded
  execution through an external agent runtime while preserving the initiating
  caller and VDB policies. The legacy `/agent/*` integration is deprecated.
- Extended the Provider gRPC boundary with negotiated
  [rich values and LOB reads](/providers/values) and
  [aggregate pushdown](/providers/pushdown). Providers that do not advertise
  these capabilities retain their previous behavior.
- Expanded the [gRPC client contract](/clients/grpc/protocol) with
  session-scoped capability negotiation, generic streamed execution,
  structured errors, transaction status and LOB operations.
- Completed the [Kubling naming migration](/naming-migration).
  Kubling-owned Java namespaces, JDBC identifiers and client property keys now
  use Kubling names, while error identifiers use `KBL` instead of
  `TEIID`. Existing Java integrations, native-client settings and monitoring
  rules must be updated.

## v26.4

- Introduced the [external gRPC provider mechanism](/providers), which moves
  source-specific connectivity, schema discovery and execution outside the
  Kubling engine.
- Removed the built-in `KUBERNETES`, `REDIS` and `CASSANDRA` data source
  implementations. These integrations are now deployed independently and
  registered in Kubling as `PROVIDER_GRPC` data sources. Existing VDBs must
  follow the [provider migration guide](/providers/migration).

## v26.3

- Introduced the Preview [gRPC client transport](/clients/grpc), with session-based authentication, streamed query results, statement execution,
explicit transaction management, TLS, IP filtering, and transport observability.
- Added the RANDINT() and RANDLONG() functions for generating random integer and long values.
- Improved native binary compatibility with systems using 64 KB memory pages, 
preventing segmentation faults reported on some ARM64 environments, including Raspberry Pi 5.

## v26.2.2

- Removed Java-related metrics from `SYSMETRICS.METRICS`, as they do not provide meaningful information when running Kubling as a native binary image.

## v26.2.1

- Improved isolation for unauthenticated HTTP requests by assigning each
  request a distinct anonymous identity.

## v26.2

- Extended Script Endpoints security integration with support for authenticated execution context propagation.
- Introduced Performance Tracer, enabling low-level execution analysis and workload-based performance tuning.
- Added RocksDB-backed buffering capabilities for large temporary workloads and memory-constrained environments.
- Added native Kubling DDL support for Portable Local data sources, allowing schema definitions without relying on database-specific syntax.
- Introduced automatic schema documentation generation from configuration schemas.

## v26.1.5
- Upgraded dependencies affected by critical vulnerabilities.
- Upgraded the JavaScript engine to improve throughput and reduce response time in cold execution contexts.

## v26.1.4
- Fixed legacy Agent API context publication so system-table metadata is scoped
  to the selected Kubling instance.

## v26.1.3
- Fixed Redis data-source queries composed exclusively of literals,
  expressions or functions.

## v26.1.2
- Fixed scripted database operations so a missing VDB returns a clear error
  instead of exposing an internal exception.

## v26.1.1
- Fixed a bug that prevented correct automatic column expansion in projections, leading to errors during row identity calculation.
- Fixed Soft Transactions continuing after a row lock could not be acquired, so
  the original locking failure is now reported immediately.

## v26.1

- Soft Transactions now support simulated MVCC, enabling consistent *read-your-writes* semantics within a transaction when using deferred execution.
- Introduced row identity–based locking requirements for Soft Transactions. Tables participating in Soft Transactions must now define a usable primary key or unique key to allow deterministic row locking and versioning.
- Added crash recovery for pending compensations. When enabled at the application level, Kubling can detect and execute unfinished compensation commands during engine startup.
- The SNMP data source now supports UPDATE operations, allowing controlled mutation of writable managed values while preserving SNMP protocol semantics.
- The Modbus data source now supports UPDATE operations, enabling write access to device registers as part of SQL-based workflows.
- Introduced table handler auto-discovery for Script Data Sources, simplifying module structure by allowing handlers to be resolved automatically based on table names.
- Added support for generated keys propagation from Script Data Sources, enabling scripts to report generated identifiers back to the engine.
- Introduced the `MAIN_HTTP_PORT` environment variable to explicitly control the port used by all HTTP-based engine services.

## v25.6.1
- Fixed an out-of-memory failure when querying `POD_CONTAINER` or
  `POD_CONTAINER_STATUS` in native deployments.
- Updated the Kubernetes base DDL.

## v25.6
- Full support for OpenTelemetry added: logs, metrics, and traces can now be exported to remote collectors or observability platforms.
- Introduced the `SOFT_TRANSACTIONS.TXDB` system table, exposing the current state and metadata of all registered Soft Transactions within the instance.
- Added new exposed metrics related to the Buffer Manager and Soft Transactions for enhanced observability.

## v25.5
- Added JavaScript HTTP endpoints, allowing you to define custom paths and handle them directly within your scripts.
- Added a new way of defining instrumentation at the application level, with support for OpenTelemetry and DataDog formats, including endpoints for pushing metrics.
- Added the `SYSREGISTRY` system table, exposing instance identity and
  traceability metadata.
- Added support for HTTP TLS certificates, affecting all HTTP-based endpoints.
- Changed the container base image to [distroless CC](https://github.com/GoogleContainerTools/distroless/tree/main/cc)
  to improve reliability on memory-constrained systems.
- Portable Local data source now supports flyway migrations.
- Fixed an issue with the MySQL data source that prevented Kubling from initializing correctly due to an incorrectly constructed connection string.

## v25.4.3
- **Kubling is now completely free, no more Community or Enterprise editions. A single, unified distribution going forward.**.
- Fixed batch/bulk `UPDATE` handling in the `routing` data source.

## v25.4.2
- Enabled top-level comparison support for the `json` data type, allowing standard operators (e.g. `=`) to be used directly in filters and joins involving JSON values.
- Added automatic detection of the `jsonb` data type in PostgreSQL with implicit transformation using the `::jsonb` suffix in pushed-down queries to avoid type-related errors.
- Updated Kubernetes API support for compatibility with the latest version.
- Enabled implicit joins with multiple tables in `FROM` for PostgreSQL and
  MySQL queries whose execution plans were previously rejected.
- Fixed an issue where prepared statement parameters were incorrectly skipped when `LIMIT` was included as a parameterized value.

## v25.4.1
- Fixed Cassandra data-source queries that could return only the first page of
  visible rows.
- Fixed an HTTP 500 response in the console when adding a data source.


## v25.4
- Added support for **SNMP**.
- Added support for **Modbus**.
- Hardened native-client deserialization against unsafe object types and
  injection attacks.
- Added IP filtering per transport, supporting both CIDR whitelisting and blacklisting.
- Introduced two new traffic metrics (per transport) to track total bytes transferred.
- Added PostgreSQL system objects (tables and views) to support standard metadata queries. Now, universal DB tools like DBeaver should be able to retrieve database metadata when using the PG transport.

## v24.5.6
- **It is now possible to use a parent field in a `synthetic` table with the format `synthetic_type 'parent', synthetic_parent_field 'another_field'` in filters.**
- Descriptor Module Bundle now supports scheduled scripts, similar to other modules.
- Resolved Out-Of-Memory (OOM) problems encountered when running certain queries on the `KUBERNETES` data source.
- Introduced a new environment variable flag, `KBL_SKIP_ENV_VAR_TEMP_FILE_ENCRYPTION`, 
to prevent the local environment variable buffer file (used for restarting the instance) from being encrypted. 
This resolves issues where containers could not be stopped and restarted due to an invalid random key.
- Enhanced the built-in DDL for the Kubernetes data source to cover reported use cases.

## v24.5.5
- Introduced a new system schema called `SYSMETRICS`, which includes a table named `METRICS` for retrieving the engine's metrics values.
- Removed the metric `kubling.engine.sql.plan.enqueued_time.max` and replaced it with `kubling.engine.sql.plan.enqueued.max`.

## v24.5.4

- Updated function module loading (SQL and Template) to support multiple modules instead of a single one. Changes to naming resolution were introduced; read more [here](/modules/functions/sql) and [here](/modules/functions/template).
- It is no longer necessary to pass random values for generated fields in `INSERT` and `UPDATE` operations. The Query Engine now identifies and handles these fields automatically before executing the final command.
- Fixed an issue that prevented the use of non-generated fields as filters with subqueries.
- Updated embedded web console to reflect the above-mentioned changes.
- Official images were renamed to `kubling/kubling-ce` and `kubling/kubling-cli`.
